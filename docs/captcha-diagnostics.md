# Диагностика VK CAPTCHA

Диагностика восстановлена в версии 4.2.3. Изменения проверены на Windows amd64 22 октября 2026 года. Релиз собирается с Go 1.26.10, включающим исправление crypto/x509 (GO-2026-6809).

Обычный журнал содержит начало попытки, способ проверки, номер потока, номер попытки, итог и длительность. Ошибки содержат очищенный JSON VK: error_code, subcode, error_msg, status, show_captcha_type и дополнительные поля, которые действительно вернул сервер. Неизвестные диагностические поля сохраняются. Значения токенов, cookies, паролей, ключей и секретных параметров запроса маскируются; исходный ответ, используемый протоколом, не изменяется.

## Как читать результат

| Запись | Значение |
| --- | --- |
| `event=CAPTCHA_SOLVE_STARTED mode=auto/manual` | Начата автоматическая или ручная попытка. |
| `event=CAPTCHA_SOLVE_RESULT outcome=token_received` | Решатель вернул непустой токен. Принятие VK ещё не подтверждено. |
| `event=CAPTCHA_SUBMIT_RESULT outcome=accepted` | VK принял повторный запрос с результатом капчи и вернул токен звонка. |
| `outcome=challenge_repeated` | VK снова запросил капчу после отправки результата. |
| `outcome=rejected` | VK вернул ошибку после отправки результата. Рядом записан очищенный ответ. |
| `outcome=request_failed` | Запрос завершился ошибкой транспорта или отказом, обработанным до разбора успешного ответа. |
| `outcome=invalid_response` | В ответе после отправки капчи отсутствует непустой токен звонка. |
| `outcome=failed` | Решатель не выдал результат. Для BOT подробности находятся в соседней строке `status=BOT response=...`. |
| `outcome=rate_limited` | Ограничение частоты запросов. Применяется существующая политика пауз. |
| `outcome=service_unavailable` | Сервис временно недоступен. Политики основного и RAW-ядра сохранены. |
| `outcome=timed_out/cancelled` | Проверка прервана таймаутом либо отменой сессии. |

`accepted` подтверждает этап авторизации VK. Работоспособность TURN-туннеля подтверждается отдельно строками `connected` и `pool serving traffic`.

Включение `-debug` добавляет очищенные ответы VK и подробности обмена: источник запроса, HTTP-статус, параметры этапа и время. Debug не отменяет маскирование секретов. Одна JSON-запись ограничена 16 КиБ, отдельная строка внутри ответа — 4096 байт; сокращение обозначается `<truncated>`. Для не-JSON HTTP-страниц записываются формат и размер тела.

При необходимости сохранить полный по времени журнал Windows:

```powershell
.\client-windows-amd64.exe <параметры подключения> -debug 2>&1 | Tee-Object -FilePath .\captcha-session.log
```

RAW-клиент использует тот же флаг `-debug`.

## Проверки

Для каждого ядра проверены 15 сценариев: автоматический/ручной токен, BOT, rate limit, недоступность сервиса, ручной таймаут, отмена, пустой токен; принятие ответа VK, отказ, повторная капча, ошибка API 10, некорректный успешный ответ; Debug выключен/включён.

Тесты используют контролируемые ответы. Живой VK, реальная ручная капча и полный VPN-сеанс на пользовательском профиле этими проверками не подтверждены. Реальные журналы проверок находятся в `dist/captcha-diagnostics-2026-10-22/state-matrix.log`, результаты запуска EXE — в `windows-startup.json`.

В основном ядре дополнительно прошли полный `go test ./...`, vet изменённых пакетов и локальный интеграционный тест TURN/TCP с восстановлением. В RAW прошли тесты captcha/manual/vkauth, session, tcprelay, сборка raw-client и vet изменённых пакетов.

Android-приложение по-прежнему хранит последние 200 строк. Сохранённый ZIP не позволяет восстановить записи, потерянные до экспорта. Принудительный перезапуск всего ядра по строке quota в Android-приложении этой правкой не изменён.
