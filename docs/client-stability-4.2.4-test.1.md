# FTcore 4.2.4-test.1 — клиентские тестовые ядра

Тестовая ветка: `codex/client-stability-4.2.4-test`. База: FTcore 4.2.3 (`fc2a5cda`).
Сборка предназначена для проверки Android/Windows клиентов с существующим сервером 4.2.3. Пакеты сервера в этот выпуск не входят. Wire-версия smux остаётся 1.

## Исправления

- TCP half-close сохраняет обратное направление до доставки ответа, включая включённую статистику.
- UDP listener читает полную датаграмму, отбрасывает неподдерживаемый размер и продолжает принимать следующие пакеты. Нештатная ошибка listener возвращается supervisor.
- Allocate одного TURN username выполняются последовательно с pacing. 486 приостанавливает новые Allocate всех его кандидатов, 508 — соответствующего endpoint. Пауза переживает переподключение в том же процессе. Ожидающие workers повторно проверяют квоту; смена реквизитов для обхода квоты не выполняется.
- TURN cooldown передаётся стартовому watchdog: мобильный timeout 15 секунд не прерывает намеренное ожидание квоты.
- Resolve/Dial/Allocate TURN имеют отмену и общий setup budget. Отмена закрывает незавершённый транспорт и транзакции.
- Владельцы FTcore-аллокаций ждут Refresh success с lifetime=0. При потере ответа ожидание ограничено 900 мс. В логах `delete_status=confirmed/unconfirmed`; ошибка удаления не инвалидирует VK credentials.
- UDP connected увеличивается после DTLS-handshake и отправки Client ID. Совместимые сообщения `Established DTLS connection` и `Closed DTLS connection` выводятся на INFO, адрес TURN передаётся отдельным `TURN server IP:` для Windows-маршрутизации. Все forwarding goroutines принадлежат жизненному циклу сессии и завершаются перед её выходом.
- Между UDP/DTLS/TURN используются ограниченные очереди пакетов. Закрытие peer будит читателя pipe.
- TCP worker panic возвращается supervisor. smux сообщает первую read/write/protocol/keepalive ошибку сразу; не требуется ждать 30-секундный keepalive для обнаружения уже известного сбоя.
- TURN renewal передаёт типизированные callbacks. Старая реализация наблюдения через лог и её тесты сохранены для совместимости, но рабочая обвязка использует новые callbacks.
- Новые TCP-соединения предпочитают менее занятую здоровую сессию, round-robin разрешает равные значения.
- Незавершённый mobile Stop сохраняет fence: новый Start не накладывается на ещё работающую предыдущую сессию.

## Payload и MTU

Консервативный предел UDP payload — **1440 байт**, с запасом под DTLS/CID, максимальный obf overhead и TURN SendIndication. Это устраняет воспроизведённую потерю пакетов при превышении буфера TURN 1600 байт.

Для встроенного relay WG/AWG допустим MTU до **1408**. Рекомендуемый default остаётся **1280**. AWG padding/junk проверяется отдельно; большой S4 уменьшает допустимый MTU. Неподдерживаемые настройки отклоняются заранее. Direct WG/AWG не получает эти relay-ограничения.

Если прежняя конфигурация использовала MTU 1420 или больше, для этой тестовой сборки установите 1280 либо допустимое значение до 1408 с учётом AWG padding. Предельный UDP payload применяется к внешней WG/AWG-датаграмме, а не к IP-пакету внутри туннеля.

## Что отложено

- Переход smux на v2 и полная изоляция медленного потока требуют согласованного изменения обеих сторон. В v1 непрочитанный поток всё ещё может заполнить общий receive budget; выбор менее занятой сессии помогает новым соединениям, но не мигрирует существующие.
- Строгий ACK принятия Client ID/backend от сервера отсутствует в текущем протоколе. Новый UDP connected подтверждает DTLS и отправку hello, но не является серверным ACK.
- Серверные admission limits, серверный UDP relay и изменение серверных defaults не входят в клиентскую сборку.
- Переработка глобального DNS-состояния и универсальное обслуживание нескольких локальных UDP-клиентов не входят в этот тестовый пакет.
- Смерть transport по-прежнему прерывает привязанные TCP-потоки; прикладные запросы автоматически не переигрываются.

## Проверки

Обычные регрессии проверяют late response после FIN, stats on/off, Windows oversized UDP, передачу ошибки listener, shared quota, cancel Allocate, startup timeout во время cooldown, shutdown fence и размеры WG/AWG.

Integration: восемь сочетаний UDP клиента (TURN TCP/UDP × none/rtpopus/rtpopus2/rtpopus3), два канала, payload 1/1280/1440/17 байт после oversized packet; недоступный DTLS peer; двадцать конкурентных workers с двумя quota-кандидатами; delete ACK и потерянный delete; существующее восстановление TURN/TCP.

Тесты smux теперь входят в `task test`; integration с race и Windows-регрессии добавлены в PR CI. Добавление CI не означает, что GitHub Actions уже запускались для этой локальной ветки.

На текущей Windows-машине доступны unit/integration, `go vet` и golangci-lint. Локальный race detector недоступен без gcc. AAR проверяется по двум ABI и встроенной версии; работа на реальном Android-устройстве и живом VK требует отдельного пользовательского прогона.

## Сборка и использование

```powershell
./scripts/build-client-test.ps1 -GoExe <путь-к-go.exe>
```

Скрипт собирает Windows amd64 EXE, Android arm64 CLI, AAR arm64-v8a/armeabi-v7a (API 24) и sources JAR. Android требует JDK, SDK и NDK; gomobile/gobind берутся из закреплённого модуля проекта, глобальные инструменты не заменяются.

Выход: `dist/test-client-4.2.4-test.1/`. Для Windows используется EXE с прежними параметрами запуска. AAR подключается в Android-приложение вместо библиотеки ядра с прежним Java namespace `com.freeturn.core`. Перед заменой сохраните рабочий файл 4.2.3 для отката. Готовые бинарники и SHA-256 перечисляются в сопровождающем manifest.

На проверке полезно собрать лог со старта: готовность DTLS, причина завершения, retry/cooldown, delete status. Успех удаления аллокации теперь отличается от неизвестного результата; `unconfirmed` не доказывает, что сервер сохранил аллокацию.
